# Dabro · Мониторинг

Telegram-бот для Linux-сервера. При запуске присылает LAN IPv4 в настроенную группу. В ней же предупреждает, когда температура Intel CPU достигает 50 °C. Повторное предупреждение возможно после охлаждения до 47 °C или ниже.

## Запуск

1. Создайте бота через [@BotFather](https://t.me/BotFather) и добавьте его в группу с правом отправлять сообщения.
2. Скопируйте `compose.override.example.yaml` в `compose.override.yaml` и заполните значения в `services.bot.environment`.
   - `BOT_TOKEN` — токен бота.
   - `GROUP_CHAT_ID` — отрицательный числовой ID группы.
   - `ALLOWED_USER_IDS` — числовые ID пользователей для доступа в личке через запятую. Пустое значение отключает личные ответы.
3. На сервере должна быть доступна существующая Docker-сеть `vpn-proxy` с HTTP-прокси `http://vpn-proxy:8080`. Проверьте сеть командой `docker network inspect vpn-proxy`.
   Для `/docker` и `/ps` выполните `stat -c '%g' /var/run/docker.sock` и внесите полученный GID в `services.collector.group_add` локального Compose-файла, например `["995"]`. Доступ к Docker API получает сборщик.
4. Запустите сервисы.

   ```sh
   docker compose up -d --build
   docker compose logs -f bot collector
   ```

Если ID неизвестны, заполните токен, соберите образ и запустите утилиту до основного бота. Она получает обновления через настроенный прокси и выводит ID при команде `/start` в личке или `/start@имя_бота` в группе. Остановите утилиту через Ctrl+C, внесите ID в Compose и запустите основной стек.

```sh
docker compose build bot
docker compose run --rm --no-deps bot python -m dabro_monitor.bot discover-ids
```

Пороги температуры, интервал замеров, время ожидания IP при запуске и адрес прокси заданы в `compose.yaml`. Если у сервера несколько интерфейсов, задайте `LAN_INTERFACE` для `collector`. По умолчанию он берёт адрес с интерфейса основного IPv4-маршрута.

Загрузка CPU считается за последний интервал замера, а средняя — за доступную историю в пределах `CPU_AVERAGE_SECONDS` (по умолчанию до 5 минут). `/disk` показывает занятое и общее место файловой системы хоста, на которой расположен источник монтирования `/host/disk`. По умолчанию используется `/etc/hostname` на системном диске. `DOCKER_LIST_LIMIT` ограничивает число строк в `/ps`.

## Команды

| Команда | Ответ |
| --- | --- |
| `/status` | CPU, температура, RAM, диск, аптайм и LAN IPv4 |
| `/cpu` | Текущая и средняя загрузка CPU, температура |
| `/temp` | Температура CPU |
| `/mem` | Занятая и общая RAM |
| `/disk` | Занятое и общее место системного диска |
| `/uptime` | Время работы сервера |
| `/ip` | LAN IPv4 |
| `/docker` | Число запущенных контейнеров |
| `/ps` | Краткий список с именем, образом и статусом контейнера |
| `/start`, `/help` | Список команд |

При включённой приватности Telegram используйте в группе `/status@имя_бота` и `/ip@имя_бота`. Данные группы доступны её участникам.

## Перезагрузка сервера

`/reboot` включается отдельно и работает в личке для пользователей из `REBOOT_USER_IDS`. После команды бот показывает кнопки подтверждения и отмены. Подтверждение одноразовое и по умолчанию действует 60 секунд.

На Linux-хосте с systemd установите слушатель сокета из корня проекта.

```sh
sudo install -D -m 0755 deploy/systemd/server-monitoring-reboot /usr/local/libexec/server-monitoring-reboot
sudo install -m 0644 deploy/systemd/server-monitoring-reboot.socket deploy/systemd/server-monitoring-reboot@.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now server-monitoring-reboot.socket
```

В локальном `compose.override.yaml` раскомментируйте настройки и том для `/reboot` из шаблона. Укажите операторов в `REBOOT_USER_IDS` через запятую. Их ID также должны входить в `ALLOWED_USER_IDS`. Примените настройки через `docker compose up -d --build`.

## Проверка на сервере

- Сверьте IP из стартового сообщения с `ip -4 addr`.
- Сверьте температуру с показаниями `sensors`, если утилита установлена. При недоступном датчике CPU бот показывает «нет данных», а остальные метрики обновляются.
- Сверьте объём диска с `df -h /etc/hostname`, число и имена контейнеров — с `docker ps`.
- Запустите команды в настроенной группе и в личке разрешённого пользователя.
